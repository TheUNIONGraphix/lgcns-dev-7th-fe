# 2026-11-05 lgcns-fe의 Prettier

- 날짜: 2026-11-05
- 앱: `lgcns-fe`
- 패키지: `prettier` ^3.9.10, 설치본 `3.9.10` (`lgcns-fe/node_modules/prettier/package.json`)
- 기준: 이 문서의 “현재 코드”는 지금 디스크의 파일이다. 저장소에 없는 훅, 에디터 설정, ESLint 연동은 있는 것처럼 쓰지 않는다.

Prettier는 이 앱의 화면을 그리지 않는다. `lgcns-fe`에서 `npm run format`을 실행할 때 Node가 CLI를 띄우고, 지원하는 파일을 그 자리에서 다시 쓴다. `lgcns-fe-next`의 `package.json`에는 `prettier` 의존성도 `format` 스크립트도 없다.

## 1. 파일이 언제 실행되는가

브라우저 페이지에는 Prettier를 불러오는 `<script>`가 없다. `lgcns-fe/index.html`의 스크립트는 앱 진입점뿐이다.

```html
<script type="module" src="/src/main.tsx"></script>
```

`async`도 `defer`도 없다. `type="module"`은 HTML 명세에서 기본적으로 지연 실행이다. 받는 동안 문서 파싱을 막지 않고, 파싱이 끝난 뒤 `DOMContentLoaded` 전에 실행된다.

| 파일 | 선언 | 실행 시점 | HTML `<script>`와의 차이 |
| --- | --- | --- | --- |
| `lgcns-fe/index.html` | `<script type="module" src="/src/main.tsx">` | 브라우저가 HTML을 파싱한 뒤 `main.tsx`를 실행한다 | 페이지 스크립트다. Prettier와 연결되지 않는다 |
| `lgcns-fe/package.json` | `"type": "module"`. 스크립트 키 `"format": "prettier --write ."` | `npm run format`이 이 패키지 디렉터리를 작업 디렉터리로 두고 그 문자열을 실행한다. `"type": "module"`은 이 패키지의 `.js`를 Node가 ES 모듈로 다루게 한다 | 브라우저 태그가 아니다. `format`은 함수 export가 아니라 npm 스크립트 문자열이다 |
| `lgcns-fe/node_modules/prettier/bin/prettier.cjs` | 첫 줄 `#!/usr/bin/env node`, 다음 `"use strict"`. `package.json`의 `"bin": "./bin/prettier.cjs"` | npm이 로컬 `prettier` 명령을 이 파일로 연결한다. Node가 프로세스를 연 뒤 CLI가 설정과 파일을 읽는다 | `.cjs`라서 부모 패키지의 `"type": "module"`과 상관없이 CommonJS다. `import`/`export` 스크립트가 아니다 |
| `lgcns-fe/.prettierrc.json` | JSON 객체. `export` 없음 | CLI가 포맷할 파일 위치에서 위로 찾아 읽고 `JSON`으로 파싱한다. 코드를 실행하지 않는다 | `.prettierrc.js`처럼 `export default`나 `module.exports`로 평가되는 설정이 아니다 |
| `lgcns-fe/.prettierignore` | gitignore 문법의 줄 목록 | CLI가 현재 디렉터리의 이 파일과 `.gitignore`를 보고 대상을 뺀다 | 스크립트가 아니다 |
| `lgcns-fe/src/main.tsx` | `import` 다음 `createRoot(...).render(...)`. export 없음 | 브라우저 모듈 그래프의 시작점이다. Prettier를 import하지 않는다 | `npm run format`이 이 파일을 고칠 수는 있다. 그 실행은 페이지 로드와 별개다 |

`async`는 스크립트를 받는 즉시 실행하고 파싱을 막지 않으며 순서가 없다. `defer`는 문서를 파싱한 뒤 적힌 순서대로 실행한다. `type="module"`은 그 지연 실행에 `import`/`export`가 더해진 것이다. Prettier CLI는 그 세 속성으로 붙지 않는다. 개발자가 `npm run format`을 실행할 때만 Node 프로세스로 돈다. `npm run dev`, `npm run build`, `npm run lint` 문자열에는 `prettier`가 없다.

참고: [HTML script 요소](https://html.spec.whatwg.org/multipage/scripting.html#the-script-element), [MDN script](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script), [Prettier CLI](https://prettier.io/docs/cli), [Prettier 설정 파일](https://prettier.io/docs/configuration).

## 2. 설정 파일이 정해진 값

`lgcns-fe/.prettierrc.json` 전체는 세 키다.

```json
{
  "semi": true,
  "singleQuote": false,
  "trailingComma": "all"
}
```

Prettier 3.9 문서의 기본값과 같다. `semi` 기본은 `true`, `singleQuote` 기본은 `false`, `trailingComma` 기본은 `"all"`이다. `trailingComma`의 `"all"`은 3.0.0에서 이전 기본 `"es5"`를 바꾼 값이다. 이 파일은 그 기본을 명시해 둔 것이다. `printWidth`, `tabWidth`, `useTabs` 같은 키는 없다. 이 패키지 트리에는 `.editorconfig`도 없으므로, 적히지 않은 항목은 Prettier 기본이다. 문서상 `printWidth` 기본은 `80`, `tabWidth` 기본은 `2`다.

`package.json`에 `"prettier"` 키는 없다. 공식 문서는 `package.json`의 그 키, `.prettierrc.json`, `.prettierrc.js` 등을 설정으로 인정한다. JS 설정은 `package.json`의 `"type"`에 따라 `export default` 또는 `module.exports`로 평가된다. 이 저장소가 고른 `.prettierrc.json`은 그 평가가 없다.

설정은 포맷 중인 파일 위치에서 부모 디렉터리로 올라가다 찾는다. 전역 설정 파일은 공식 문서가 일부러 지원하지 않는다. 프로젝트를 다른 컴퓨터로 복사해도 같은 결과가 나오게 하려는 이유다. `lgcns-fe` 안의 파일을 포맷하면 이 `.prettierrc.json`을 만난다. `lgcns-fe-next`에는 같은 파일이 없다.

| 옵션 | 이 파일의 값 | 포맷 결과 | 명세에서 그 문법이 하는 일 |
| --- | --- | --- | --- |
| `semi` | `true` | 문장 끝에 세미콜론을 넣는다 | `false`이면 Prettier는 ASI로 다음 줄이 붙을 수 있는 자리에만 세미콜론을 남긴다. ECMA-262의 Automatic Semicolon Insertion은 세미콜론이 없을 때 파서가 넣는 규칙이다 |
| `singleQuote` | `false` | 문자열은 큰따옴표를 기본으로 한다 | JSX 따옴표는 이 옵션이 아니라 `jsxSingleQuote`다. 이 파일은 `jsxSingleQuote`를 적지 않았다. 따옴표 개수 때문에 반대 따옴표가 더 적으면 Prettier는 그쪽으로 고른다 |
| `trailingComma` | `"all"` | 여러 줄인 쉼표 목록의 마지막에도 쉼표를 넣는다. 한 줄 배열에는 넣지 않는다 | `"all"`은 함수 매개변수와 호출, TypeScript 타입 매개변수까지 포함한다. 함수 쪽 후행 쉼표는 ES2017이다. `"es5"`는 객체와 배열처럼 ES5에서 유효한 곳만, `"none"`은 후행 쉼표가 없다 |

참고: [Prettier 옵션](https://prettier.io/docs/options), [MDN 후행 쉼표](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Trailing_commas), [MDN ASI](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Lexical_grammar#automatic_semicolon_insertion), [ECMA-262 Automatic Semicolon Insertion](https://tc39.es/ecma262/#sec-automatic-semicolon-insertion).

## 3. `npm run format`이 건드리는 파일

스크립트는 `prettier --write .`다. `.`는 현재 디렉터리라서, `lgcns-fe`에서 npm을 돌리면 그 디렉터리와 하위만 대상이다. `--write`는 처리한 파일을 그 자리에 덮어쓴다. 공식 문서는 이 동작을 `eslint --fix`에 가깝다고 적는다. 검사만 하는 `--check`는 이 스크립트에 없다.

디렉터리를 넘기면 CLI는 확장자와 Prettier가 아는 파일 이름으로 지원 파일을 재귀적으로 찾는다. `node_modules`는 CLI가 기본으로 뺀다. 심볼릭 링크는 따라가지 않는다.

무시 목록은 두 파일이다. 공식 CLI는 작업을 시작한 디렉터리의 `.gitignore`와 `.prettierignore`를 본다.

`lgcns-fe/.prettierignore`에 적힌 줄:

- `node_modules`
- `dist`
- `dist-ssr`
- `.vite`
- `pnpm-lock.yaml`
- `package-lock.json`

`lgcns-fe/.gitignore`도 같이 적용된다. 거기에는 `logs`, `*.log`, `node_modules`, `dist`, `dist-ssr`, `*.local`, `.idea`, `.DS_Store`, `.vscode/*` 등이 있다. `!.vscode/extensions.json`은 gitignore의 부정 패턴이다. Prettier는 이 파일을 gitignore 문법으로 읽는다.

소스에는 `prettier-ignore` 주석이 없다. 그 주석은 파일 전체가 아니라 다음 AST 노드만 포맷에서 빼는 공식 문법이다. 이 앱은 그 주석을 쓰지 않는다.

`format`은 `lint`나 `build` 앞에 붙어 있지 않다. 저장할 때 에디터가 돌리는 설정 파일도 이 패키지에 없다. 포맷은 `npm run format`을 실행했을 때 일어난다.

참고: [Prettier CLI `--write`](https://prettier.io/docs/cli), [Ignoring Code](https://prettier.io/docs/ignore).
