1. Next.js 공식 문서

버전은 프로젝트에 설치된 16.4.3 문서 기준입니다. 아래 주소는 nextjs.org의 App Router 문서입니다.

프로젝트 구조

문서 Project structure and organization

https://nextjs.org/docs/app/getting-started/project-structure

소스 app/, component/

폴더가 주소를 만들고, 라우트가 아닌 파일은 URL에 안 올라갑니다. 오늘 화면 컴포넌트는 app 밖 component/에 있으므로 /component라는 주소는 생기지 않습니다. (main), (auth)처럼 괄호 폴더는 같은 문서의 Route groups 절과 아래 Route Groups 문서가 설명합니다.

실제 감싸기 순서는 이렇습니다. 루트 app/layout.tsx가 html과 body를 만듭니다. /는 그 안에 (main)/layout.tsx의 Header가 한 번 더 감쌉니다. /login은 Header 대신 (auth)/layout.tsx를 탑니다. 루트 레이아웃의 LayoutProps<"/">는 이 layout 문서와 TypeScript 문서가 설명하는, 라우트에 맞춰 생성되는 props 타입입니다.

소스 app/(main)/, app/(auth)/

괄호 폴더 이름은 URL에 들어가지 않습니다. app/(auth)/login/page.tsx의 주소는 /auth/login이 아니라 /login입니다. 그룹을 나눈 이유는 같은 깊이에서 레이아웃을 다르게 쓰기 위해서입니다. 메인에는 헤더, 인증 화면에는 AuthLayout만 붙습니다.

링크와 이동

문서 Linking and Navigating · Link

https://nextjs.org/docs/app/getting-started/linking-and-navigating

https://nextjs.org/docs/app/api-reference/components/link

소스 component/molecules/DesktopNavigation.tsx, component/molecules/MobileNavigation.tsx, component/molecules/LogoItem.tsx

앱 안 이동은 <a> 대신 Link를 씁니다. 데스크톱 메뉴는 /, /about, /contact로 연결됩니다. 오늘 app 안에 있는 페이지는 /와 /login뿐입니다. /about과 /contact용 page.tsx는 아직 없습니다.

로고의 Link는 href="https://www.lgcns.com/"와 target="_blank"입니다. 외부 주소도 Link로 열 수 있고, 이건 앱 내부 클라이언트 이동이 아닙니다.

서버 컴포넌트와 클라이언트 컴포넌트

문서 Server and Client Components · use client

https://nextjs.org/docs/app/getting-started/server-and-client-components

https://nextjs.org/docs/app/api-reference/directives/use-client

소스 component/molecules/MobileNavigation.tsx만 "use client"

App Router 컴포넌트는 기본이 서버 컴포넌트입니다. useState처럼 브라우저 상태가 필요하면 파일 맨 위에 "use client"를 붙입니다. 모바일 메뉴의 isOpen이 그 경우입니다. Header, DesktopNavigation, BannerSwiperItem에는 이 지시어가 없어서 서버 컴포넌트로 남습니다. 클라이언트 파일이 서버 컴포넌트를 import하면 그 경계가 따라오므로, 상태가 필요한 파일만 클라이언트 경계를 두는 것이 이 문서의 요지입니다.

이미지

문서 Image · images 설정 · 호스트 미설정 오류

https://nextjs.org/docs/app/getting-started/images

https://nextjs.org/docs/app/api-reference/components/image

https://nextjs.org/docs/app/api-reference/config/next-config-js/images

https://nextjs.org/docs/messages/next-image-unconfigured-host

소스 component/molecules/BannerSwiperItem.tsx, component/molecules/LogoItem.tsx, next.config.ts의 images.remotePatterns

next/image의 src가 외부 주소이면, 그 호스트를 remotePatterns에 적어야 합니다. 오늘 i.pinimg.com이 빠져 있어서 런타임 오류가 났고, protocol, hostname, pathname: "/**"를 넣어 해결했습니다. 같은 배열에 www.lgcns.com도 있습니다. 로고 Image가 이 호스트의 SVG를 가리킵니다.

공식 Image 문서는 SVG를 기본으로 최적화하지 않습니다. SVG를 허용하려면 images.dangerouslyAllowSVG가 따로 필요합니다. 로고 소스는 SVG이고, 이 설정은 next.config.ts에 아직 없습니다.

width와 height는 배너(1000)와 로고(100)에 모두 넘깁니다. 정적 import가 아닌 문자열 src에는 이 두 값이 필요합니다. component/atoms/LogoImage.tsx는 next/image가 아니라 <img>라서 이 제한을 타지 않습니다. 지금 로고 화면은 LogoItem이 그리고, LogoImage는 아직 연결되지 않았습니다.

Gothic A1은 변수는 만들지만 className에는 아직 없습니다. globals.css의 h1은 var(--font-black-han-sans)를 쓰고, @theme inline은 Geist 변수를 Tailwind의 --font-sans, --font-mono로 연결합니다. 폰트 문서와 Tailwind @theme 문서가 이 한 줄에서 만납니다.

문서 cacheComponents · partialPrefetching · turbopack · agentFeedback

소스 next.config.ts

  • cacheComponents: true는 use cache와 정적 셸을 켭니다. 오늘 컴포넌트에는 use cache가 아직 없습니다. 설정만 켜진 상태입니다.
  • partialPrefetching: true는 cacheComponents와 같이 둡니다. 공식 문서는 이 값을 비우면 경고가 난다고 합니다. Link의 프리페치 동작이 이 설정의 영향을 받습니다.

  • experimental.agentFeedback는 오늘 화면 기능과 무관합니다. 설정 파일에 켜져 있어 문서 주소만 적습니다.

테마 변수와 @theme inline

문서 Theme variables

https://tailwindcss.com/docs/theme

소스 app/globals.css의 @theme inline, app/layout.tsx의 next/font

@theme에 적은 CSS 변수가 유틸리티 클래스를 만듭니다. 예를 들어 --color-background는 색 유틸리티와 연결됩니다. inline은 테마 값을 별도 변수로 한 번 더 복사하지 않고, 이미 있는 변수를 그대로 가리키게 합니다. 공식 테마 문서의 예가 @theme inline { --font-sans: var(--font-inter); } 형태입니다.

오늘 코드는 그 예와 같습니다. next/font가 --font-geist-sans를 만들고, @theme inline이 --font-sans: var(--font-geist-sans)로 받습니다. --color-background와 --color-foreground도 :root 값을 가리킵니다. 다크 모드는 prefers-color-scheme로 :root 값만 바꿉니다.

소스 DesktopNavigation.tsx의 hidden md:flex, MobileNavigation.tsx의 md:hidden

접두사 없는 클래스는 모든 너비에 적용되고, md:는 768px(48rem) 이상에서만 적용됩니다. 모바일 전용 스타일을 만들 때 sm:을 "작은 화면"으로 쓰면 안 됩니다. 작은 화면은 접두사 없는 클래스이고, md:가 그 위를 덮습니다.

데스크톱 목록은 기본 hidden이었다가 md:flex로 나타납니다. 햄버거와 펼친 메뉴는 md:hidden이라 768px 이상에서는 숨습니다. items-center와 gap-4는 flex 컨테이너의 정렬과 간격입니다.

클래스 우선순위와 tailwind-merge

문서 tailwind-merge (Tailwind 공식 패키지는 아님)

https://github.com/dcastil/tailwind-merge

소스 component/atoms/CustomTitle.tsx, component/atoms/LogoImage.tsx, package.json의 tailwind-merge

Tailwind 유틸리티는 클래스 문자열에 나중에 적었다고 이기지 않습니다. 같은 속성이면 생성된 CSS 안에서의 순서가 이깁니다. 그래서 text-white ${className}처럼 이어 붙이면, 밖에서 text-red-500을 넘겨도 흰색이 남을 수 있습니다.

twMerge("text-2xl font-bold text-center text-white", className)는 겹치는 유틸리티만 나중 값으로 바꿉니다. BannerSwiperItem이 className="text-red-500"를 넘기면 결과 클래스는 text-2xl font-bold text-center text-red-500입니다. 크기, 굵기, 정렬은 기본값이 남습니다. LogoImage도 w-full h-full object-cover 위에 같은 방식으로 className을 올립니다.

3부의 shadcn cn()은 이 twMerge에 clsx를 더한 함수입니다. 지금 코드는 clsx 없이 twMerge만 씁니다.

shadcn은 Tailwind v4의 @theme과 @theme inline을 지원한다고 이 문서에 적혀 있습니다. 새 프로젝트의 기본 스타일은 new-york이고, 색은 OKLCH를 씁니다. 오늘 globals.css의 색은 #ffffff, #171717 같은 직접 값입니다. shadcn 테마를 넣으면 이 파일의 :root와 @theme에 컴포넌트용 색 변수가 추가됩니다. 기존 --background, --foreground 이름과 겹치는지 그때 맞춰야 합니다.

오늘 소스와 대응되는 컴포넌트

오늘 소스지금 상태대응 문서연결되는 기술
component/atoms/Button.tsx 빈 파일. 배너의 "View More"는 이 컴포넌트가 아니라 BannerSwiperItem.tsx의 <button> https://ui.shadcn.com/docs/components/button Radix Slot, CVA variant, Tailwind. variant와 size로 스타일을 나눕니다. 지금 CustomTitle이 className으로 덮어쓰는 방식과 비슷하게, Button도 className을 cn()으로 받습니다.
component/molecules/DesktopNavigation.tsx ul과 next/link. hidden md:flex https://ui.shadcn.com/docs/components/navigation-menu Radix Navigation Menu. 링크 자체는 계속 next/link를 넣을 수 있습니다. 반응형으로 숨기는 클래스는 Tailwind md:가 담당하고, shadcn이 그 레이아웃을 대신하지는 않습니다.
component/molecules/MobileNavigation.tsx "use client", useState, 햄버거 SVG, sr-only https://ui.shadcn.com/docs/components/sheet Radix Dialog 기반의 옆면 패널. 열림 상태를 직접 useState로 들고 있는 지금 구조를, Sheet의 open으로 옮기는 자리입니다. 클라이언트 컴포넌트여야 하는 점은 Next use client 문서 그대로입니다.
component/atoms/CustomTitle.tsx twMerge로 제목 단계와 클래스를 받음 https://ui.shadcn.com/docs/installation/manual 의 cn 절 shadcn에 같은 제목 컴포넌트는 없습니다. 연결점은 클래스 병합뿐입니다. Typography 예시는 https://ui.shadcn.com/docs/components 목록의 별도 타이포그래피 컴포넌트가 아니라 테마의 글자 스타일입니다.

SubTitle.tsx도 비어 있습니다. shadcn 문서에 1:1로 대응하는 컴포넌트는 없고, 설치 후 타이포그래피 클래스나 Button·제목 조합으로 채울 자리입니다.

넣기 전에 읽을 순서

  1. Next.js 설치 문서. 별칭과 globals.css가 이미 있는지 확인하는 절차입니다.
  2. Tailwind v4 문서. @theme inline과 기존 색 변수가 어떻게 합쳐지는지 봅니다.
  3. Manual 설치의 cn. CustomTitle, LogoImage의 twMerge와 같은 역할입니다.
  4. Button, Navigation Menu, Sheet. 빈 Button.tsx와 두 네비게이션 파일을 바꿀 때 엽니다.
